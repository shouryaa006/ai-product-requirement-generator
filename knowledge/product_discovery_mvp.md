# Product Discovery and MVP Principles

The Minimum Viable Product (MVP) is the smallest, simplest version of a product that can be released to early customers to gather maximum validated learning with the least effort.

## Core MVP Principles

1. **Avoid Over-Engineering**: Focus strictly on the "Must-Have" features. Do not build advanced search, multi-tiered subscription levels, or custom chat servers if a simple keyword search, basic booking flow, and standard email notifications are enough to solve the core problem.
2. **Build-Measure-Learn**: The fundamental feedback loop of lean startup methodology. Build a feature, measure user interaction via analytics and interviews, and learn whether to pivot or persevere.
3. **Faking the Backend (Wizard of Oz)**: Before writing complex automated scheduling algorithms, run the booking manually behind the scenes. This validates user demand before investing massive engineering resources.

## Defining the MVP Scope

Using a prioritized list of user stories, map them to MVP release milestones:

- **In MVP (Release v1.0)**:
  - User signup and login (CS email required)
  - Search tutors by course code
  - Basic calendar booking
  - Email notification upon confirmation
- **Out of MVP (Post-v1.0)**:
  - Automated SMS reminders
  - Integrated audio/video video conferencing room
  - Promo code discounts and referral bonuses
  - Multi-user group tutoring sessions
